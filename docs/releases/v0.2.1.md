# Release Notes — NutriFlow v0.2.1

**Data:** 2026-04-18  
**Tipo:** Patch critica  
**Deployment:** https://nutriflow-app-sigma.vercel.app

---

## Root cause dei bug

Tutti i bug segnalati (piano non visibile, chat non funzionante, questionario bloccato, notifica mancante) avevano la **stessa root cause**: `patients.auth_user_id` non impostato per i pazienti già registrati.

La funzione `my_patient_id()` (usata nelle policy RLS di piano alimentare, messaggi, misurazioni) restituisce NULL se `patients.auth_user_id` è NULL → RLS filtra via tutti i dati del paziente.

La migrazione 009 conteneva già il backfill via `auth.users.email`, ma se il paziente si era registrato con un'email diversa da quella inserita nella scheda paziente (o se si era registrato dopo il backfill), il link non veniva stabilito.

---

## Fixes applicate

### 1. Piano alimentare (portale paziente)
- **Causa**: `my_patient_id()` → NULL → RLS blocca `meal_plans`
- **Fix**: migrazione 010 (backfill + self-healing) + `patient_self_link()` chiamato al caricamento portale

### 2. Chat
- **Causa**: stessa RLS su `conversations` e `messages`
- **Fix**: stesso (migrazione 010)

### 3. Questionario submit
- **Causa**: la tabella esiste ed era accessibile, ma `nutritionist_id` era NULL → nessuna notifica e `patient_id` non collegato
- **Fix**: trigger `on_patient_feedback_submitted` ora usa fallback email + fixa il link al momento del submit

### 4. Notifica nutrizionista
- **Causa**: trigger non riusciva a risolvere `nutritionist_id` senza `auth_user_id`
- **Fix**: stessa logica aggiornata nel trigger

### 5. Storico rilasci
- Già completato in v0.2.0 (CHANGELOG, docs/releases, scripts/release-notes.mjs)
- Questa release aggiunge v0.2.1 come esempio di flusso completo

## Migrazione da eseguire in Supabase

**Obbligatoria** per attivare le fix. Eseguire nel SQL Editor di Supabase Dashboard:

```
supabase/migrations/010_auth_link_selfheal.sql
```

La migrazione è idempotente (si può eseguire più volte senza effetti collaterali).

**Operazioni eseguite dalla migrazione:**
1. Backfill `patients.auth_user_id` via `profiles.email` (più aggressivo del precedente via `auth.users.email`)
2. Correzione `profiles.role = 'patient'` e `profiles.nutritionist_id` per account già linkati
3. `handle_new_user()` aggiornata con `ON CONFLICT DO UPDATE`
4. `on_patient_feedback_submitted()` aggiornata con fallback email + self-healing
5. Nuova funzione RPC `patient_self_link()` per auto-link a caricamento portale
